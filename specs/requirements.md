# Requirements & Acceptance Criteria

Source of truth for **what** the system must do. Design rationale lives in `DECISIONS.md` (3 ADRs) and `specs/architecture.md`; assumptions in `specs/assumptions.md`; tasks in `specs/tasks.md`.

**Provenance tags — never mix them up:**
- **SEZ-*** — official Sezzle requirement, quoted/located in `assessment/PROMPT.md`, `assessment/SUBMISSION.md`, `data/policies/*`, or `cases/golden_visible.jsonl`.
- **OWN-*** — engineering choice **approved by the project owner** on 2026-09-27 (`docs/planning/prompts/P-004-owner-approved-direction.md`). Not a Sezzle requirement.
- **SEC-*** — security requirements derived from SEZ + OWN (source listed per row).

Agents MUST NOT change a requirement to fit their code. Changes require an explicit owner decision recorded in `docs/decision-log.md`.

Status values: `todo | doing | done | cut (reason)`. Verification IDs refer to `specs/tasks.md` (T-*), tests (`tests/…`), and eval categories (`specs/evaluation.md`).

## 6. Security requirements (SEC)

| ID | Requirement | Derived from | Acceptance criteria | Verify |
|---|---|---|---|---|
| SEC-01 | `user_id` comes only from the harness input; never parsed from the question; never a tool parameter | SEZ-L02 (hostile order IDs); OWN-05 | Tool schema has no user field; the closure binds the case's user_id | `tests/test_tools.py` |
| SEC-02 | Order access scoped to the caller: filter by user **before** matching | SEZ-L02 | Foreign order IDs never returned | `tests/test_tools.py` |
| SEC-03 | Foreign and nonexistent order IDs produce **identical** `not_found` results (no existence oracle) | SEZ-L02 | Byte-identical tool payloads | `tests/test_tools.py` |
| SEC-04 | Read-only tool surface; no functions that reschedule, refund, waive, pause, file disputes, or change limits | policies 02–12 "human-only"; OWASP LLM06 | Tool registry = {get_my_orders}; validator rejects action claims | `tests/test_tools.py`, `tests/test_validator.py`; eval label UNSAFE_PROMISE = 0 |
| SEC-05 | Input validation: question length cap; control characters stripped; unknown `user_id` handled without data | OWASP LLM01/10 | Over-cap input truncated + flagged; unknown user → no tool data, graceful answer | `tests/test_guards.py` |
| SEC-06 | Output validation (narrow): schema/enums; cited policy IDs ⊆ corpus; no order IDs outside the caller's; order-specific $/dates must match this case's tool result (after canonicalisation); no past-tense action claims; no "your limit is"-style limit disclosure | SEZ-F05/P09/P12; OWASP LLM05/09 | Violations → 1 repair attempt → safe escalation | `tests/test_validator.py` |
| SEC-07 | Consumption caps: ≤1 tool round per case, max output tokens, per-call timeout, bounded retries, batch-level call counter | SEZ-N01; OWASP LLM10 | Loop terminates; retries ≤ configured attempts | `tests/test_loop.py` |
| SEC-08 | Prompt-injection posture: user text delimited as untrusted data; policies only from the corpus loader; tool results passed as data | OWASP LLM01 | Injected "policy"/"system" text doesn't change routing/authorization | categories `injection_*`; label INJECTION_FOLLOWED = 0 |
| SEC-09 | One-way escalation tripwire (fraud, hardship, explicit human-only action requests, explicit human request — `specs/security.md` §3) can only **add** escalation; the LLM still writes the reply | SEZ-P03/P05/P07/P09/P11/P12; SEZ-F01; A-15 | Tripwire never produces answer text; informational questions don't trigger it | `tests/test_guards.py`, `tests/test_routing.py` |
| SEC-10 | Safe failure: provider/validation failure → fixed, non-substantive escalation message ("I can't complete this right now; connecting you with a support specialist") with route `escalate` | OWN-15 | Only failure path uses the template; trace records the cause | `tests/test_failures.py` |
| SEC-11 | Fraud mode: order tool withheld for the turn; answer contains no order IDs, amounts, merchants | SEZ-P11 | label FRAUD_READBACK = 0 | `tests/test_loop.py`; category `fraud_readback` |
| SEC-12 | Cross-case isolation: no state shared between cases except immutable resources | OWN-04 | Sequential u001→u002 run: no u001 identifiers in u002 trace/answer | `tests/test_isolation.py` |
| SEC-13 | Secrets: key only via env/`.env` (git-ignored); never logged, traced, or committed; gitleaks in CI | SEZ-S02; OWN-08 | gitleaks clean; trace schema has no headers/keys | CI; T-17 |
| SEC-14 | Data handling: assessment material is sent only to an approved, **paid-terms** LLM project (see `specs/assumptions.md` A-10) | SEZ-S02; Gemini terms | Owner confirms billing before the first real run | readiness checklist |
